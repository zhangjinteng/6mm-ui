## 确认 6mm-ui 是否支持「组题功能」
- 当前版本 `@work-gpt/6mm-ui@0.4.6`，是面向 6MM 产品（交易/商户后台）的通用 Vue 3 组件库，非问卷/组题/考试框架。
- 全量搜索（src + docs + 父项目 6mm-agent-console，排除 node_modules）：无 `组题/题目/题库/试卷/题组/问卷/答题/survey/questionnaire` 相关实现。
- 组件清单（docs/components.md）：基础能力(11)、表单(13)、数据展示(19)、导航(7)、反馈(8)、其他(1)。无问卷/组题专用组件。
- 结论：当前版本不支持组题功能，且无对应文档链接。组题属业务级能力，超出该 UI 库范围（README「当前非目标」明确不提供业务状态/路由/接口）。
- 替代：可用现有表单原语（MmForm/MmInput/MmRadioGroup/MmCheckboxGroup/MmSelect/MmInputNumber/MmDatePicker/MmUpload）自行拼装题目输入；组卷/题库/提交等业务逻辑需在业务侧实现。

## 确认 6mm-ui 主题功能（对比：组题不支持，主题支持）
- 主题功能**受支持**，是框架核心能力（非业务功能）。
- 机制：通过根节点 `data-mm-theme="light|dark"` 切换；token 全部为 `--mm-*` CSS 变量，定义在 `src/styles/tokens.css`（light/dark 两套，覆盖 color/font/space/radius/shadow/z/duration 等）。
- 切换方式 3 种：(1) 直接 `document.documentElement.dataset.mmTheme = 'dark'`；(2) `MmAppHeader` 的 `v-model:theme` + `theme-change` 事件（组件只回传值，宿主负责写入根节点）；(3) 宿主 CSS 覆盖 `--mm-*` token（如 `[data-mm-theme='light']{--mm-color-primary:#087765}`）。
- 约束：主题属性建议设在 `<html>`/`<body>`；Dialog/Drawer/Popover/Message 等 Teleport 到 body，根级主题才能保证浮层一致。`prefers-reduced-motion` 会自动将过渡时长归零。
- 文档：README.md「主题」章节 + docs/components.md（无独立主题文档页）。

## 验证 playground `/components` 是否展示全部组件（无头 Playwright 实测）
- 结论：**`/components` 不全**。它并非独立目录页，而是落地首页 `App.vue` 内嵌的「组件预览」区块（main.ts 仅把 `/component-info`、`/pro-table`、`/sidebar-nav` 当作特殊入口，其余路径含 `/components` 都 fallback 到 App 落地页）。
- 实测 `/components` 用 `[data-mm-component]` 去重共渲染 **54 种**组件，但注册表（`src/components/index.ts`）共 **67 个**组件名（59 父级 + 8 子组件）。
- 缺失的 8 个父级组件：dialog / drawer / loading / message / message-box / tooltip / pro-table-cursor-pagination / pro-table-pagination（整组「反馈」浮层 + 两个 ProTable 分页子件未出现在预览）。
- 页面自述「全部公开组件的实时演示」不准确（属 curated teaser）。
- 完整目录页应是 `ComponentInfoPage`（`/component-info`，测试 component-catalog.spec.ts 断言 59 个 section）。但**当前运行的 dev server（5199）显示 v0.4.3、而 package.json 为 0.4.6**，且 `/component-info` 实测也回退到落地页（0 section）——疑似 dev server 跑的是旧构建，需重启 `npm run dev` 才能加载当前源码（含 ComponentInfoPage）。
